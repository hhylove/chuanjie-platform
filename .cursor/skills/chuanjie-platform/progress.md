## 开发纪律（强制）

1. **文档先行**：阶段/功能须先在 skill 目录写出骨架或拆解 md 并写明白，挂到 progress，评审通过后才能开发（见 SKILL「文档先行」）  
2. 先拆解后动手；未评审不得编码  
3. 子任务 1～3 天可验收；金额/库存/权限/状态机写清  
4. 每次开发更新总表 + 日志  
5. 无进度更新不合并；注释按规范（含**配置项**必须说明干什么用）  
6. 状态：`未拆解` / `拆解中` / `待评审` / `开发中` / `联调中` / `已完成` / `暂停`  

**阶段文档门槛：** S0→[s0-scaffold.md](s0-scaffold.md)；S1～S5 对应 `s1-platform-oa.md` … `s5-data-ai.md`（未产出禁止开发该阶段）。

## S2-01 创业者档案 — 详细拆解（待评审）

### 目标

一次建档多处复用，减少反复填表与口头对齐。

### 范围

主档 CRUD、列表详情、能力评估、字段级权限与审计。  
本阶段不做：完整申请审批流（挂 S2-02 + S1 统一审批）、创业者端复杂自助。

### 依赖

S0 可联调；建议 S1-01/02 权限底座就绪后落地更稳。

### 落位

- 后端：`project` 模块内创业者域（或独立 entrepreneur，不进 platform 堆业务）  
- 前端：`admin-web/modules` 对应中心  
- API：`/admin-api/v1/entrepreneurs`  

### 子任务

| ID | 内容 | 验收 |
|----|------|------|
| E1 | 表结构+迁移+COMMENT | 字段均有 COMMENT |
| E2 | 状态机 draft/active/inactive；手机号唯一 | 单测 |
| E3 | CRUD + 分页 API + 注释 | OpenAPI/注释齐全 |
| E4 | 能力评估历史 | 可查当前+历史 |
| E5 | 字段级权限 | 后端强制 |
| E6 | 审计 | 敏感查看/变更留痕 |
| E7 | admin 列表详情表单评估页 | 无直调 Axios |
| E8 | 端到端验收 | 清单通过 |

### 核心表（草案）

`entrepreneur_profile`：entrepreneur_no、name、mobile、证件、user_id、status、source、remark + 审计字段  
`entrepreneur_capability_assessment`：entrepreneur_id、score、level、summary、assessor、assessed_at + 审计字段
